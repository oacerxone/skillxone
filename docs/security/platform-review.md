# Platform security review (v0.1.0-beta)

A review of the platform itself (web app, worker, deployment files) against the threat list in [overview.md §9](../architecture/overview.md#9-platform-security-summary), done in Phase 10 on 2026-11-16. The skill scanner's own accuracy is covered in [live-catalog-review.md](live-catalog-review.md).

This review was done by the same agent that wrote the code. Treat it as a checklist with evidence, not as an independent audit. An independent review is recommended before production use.

## Findings fixed during the review

| Finding                                                                                                                                          | Severity               | Fix                                                                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| The web app sent no Content-Security-Policy, although the design called for one                                                                  | Medium                 | `apps/web/proxy.ts`: per-request nonce, `'strict-dynamic'`, `object-src 'none'`, `base-uri 'none'`, `frame-ancestors 'none'`. Tested in `e2e/a11y.spec.ts` (header present, no violations, hydration works). |
| Removing someone from `ADMIN_GITHUB_IDS` did not affect their existing sessions until they signed in again (the role was read from the database) | Medium                 | The allowlist is applied on every request (`apps/web/lib/auth.ts`). Tested in `e2e/admin.spec.ts` ("removing someone from the allowlist…").                                                                  |
| Read-then-write transactions on SQLite could fail with "database is locked" under concurrent writers                                             | Low (availability)     | `writeTransaction` uses `BEGIN IMMEDIATE`. Found in Phase 9; tested in `packages/database/src/transaction.test.ts`.                                                                                          |
| `.gitignore` kept a security source file out of git (`packages/security/src/data/domains.ts`)                                                    | High (build integrity) | Rule anchored to the top level. Found in Phase 9 by deploying from a fresh clone.                                                                                                                            |

## Threats and controls

| Threat                                                                     | Control                                                                                                                                                                                                          | Evidence                                                                                                                                                                |
| -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Malicious Markdown in SKILL.md (XSS, tracking images, `javascript:` links) | unified/remark/rehype with `rehype-sanitize`, no raw HTML, images turned into links, only `https:`/`mailto:` links, rendered without `innerHTML`; CSP as a second layer                                          | `apps/web/lib/markdown.test.ts`; all 668 live SKILL.md files rendered with no unsafe tags (Phase 2); static export test asserts no script, iframe or img in skill pages |
| Executing repository code                                                  | The scanner reads stored text only; the installer produces text; the web app never runs commands; gitleaks (optional) reads copies of files                                                                      | `packages/security`, `packages/installer`; architecture rule in AGENTS.md                                                                                               |
| Command injection through install commands                                 | Owner, repo and commit allowlisted and rejected otherwise; skill names quoted per shell; leading dashes and control characters refused                                                                           | `packages/installer/src/installer.test.ts`: hostile names run through `/bin/sh`, nothing executes                                                                       |
| SQL injection                                                              | Kysely parameterised queries; the one `sql.raw` uses constant weights; FTS query tokens are quoted                                                                                                               | `packages/search/src/search.test.ts` (hostile query strings)                                                                                                            |
| SSRF                                                                       | The server never fetches a user-supplied URL; submissions are parsed to owner/repo and only queued; OAuth calls fixed GitHub endpoints                                                                           | `apps/web/lib/security.test.ts` (non-GitHub URLs rejected)                                                                                                              |
| CSRF                                                                       | HMAC token bound to the session on every admin mutation and on public writes that carry a session cookie; same-origin check on all mutations; JSON-only public endpoints force a CORS preflight                  | `e2e/admin.spec.ts` (table-driven over every endpoint), `apps/web/lib/security.test.ts`                                                                                 |
| Broken access control                                                      | `requireStaff()` in every admin page (real 401/403 via `unauthorized()`/`forbidden()`); role checks in every admin endpoint; roles from the environment allowlist                                                | `e2e/admin.spec.ts`: every page and endpoint × no session, user, moderator, admin                                                                                       |
| Session theft or fixation                                                  | Random 256-bit token; only its SHA-256 stored; new token per sign-in; `HttpOnly`, `SameSite=Lax`, `Secure` on HTTPS; 7-day expiry; logout deletes                                                                | `packages/database/src/community.test.ts`                                                                                                                               |
| OAuth token leakage                                                        | No scopes requested; token used once to read the profile, then dropped; state cookie checked in constant time                                                                                                    | `apps/web/lib/security.test.ts` (token never in the returned profile)                                                                                                   |
| Open redirect                                                              | Admin `back` parameter limited to `/admin` paths; sign-in redirects only to fixed paths                                                                                                                          | `e2e/admin.spec.ts` ("back link cannot redirect off the admin area")                                                                                                    |
| Spam and abuse of public writes                                            | Rate limits (10 an hour per client), size caps, duplicate detection, moderation before indexing; only triaged reports affect ranking                                                                             | `e2e/admin.spec.ts`, `packages/database/src/community.test.ts`                                                                                                          |
| Regex denial of service in the scanner                                     | Linear-time patterns with bounded gaps; lines cut to 2,000 characters; per-scan timeout ⇒ FAILED                                                                                                                 | `packages/security/src/engine.test.ts` (hostile input under 2 s, timeout test)                                                                                          |
| Secret leakage                                                             | Secrets only in `.env`; env errors name the variable, not the value; credential findings redacted in reports                                                                                                     | `packages/shared/src/env.test.ts`, `packages/security/src/engine.test.ts`                                                                                               |
| Privacy of reporters                                                       | IP addresses never stored, only an HMAC with a generated secret; no analytics                                                                                                                                    | `packages/database/src/community.test.ts`                                                                                                                               |
| Supply chain                                                               | Actions pinned by commit SHA; Docker base images pinned by digest; Dependabot with a 7-day cooldown; dependency audit, gitleaks and CodeQL workflows; new dependencies chosen at versions at least two weeks old | `.github/workflows/*`, `Dockerfile`, `.github/dependabot.yml`                                                                                                           |
| Clickjacking                                                               | `frame-ancestors 'none'` and `X-Frame-Options: DENY`                                                                                                                                                             | `apps/web/proxy.ts`, `apps/web/next.config.ts`                                                                                                                          |

## Accepted risks and limits

- **`minimatch` advisory (moderate, GHSA-g3hv-75wg-m249)** in the lint toolchain (`typescript-eslint`). It is a development dependency that only ever sees glob patterns from this repository. `pnpm audit --prod` reports no known vulnerabilities. It will be resolved when typescript-eslint updates.
- **`style-src 'unsafe-inline'`** is allowed. Inline styles cannot run code, and blocking them breaks layout.
- **The in-memory rate limiter** resets when the process restarts and is not shared across several web processes. The supported topology is one web process; behind several, rate-limit in the reverse proxy.
- **Without `TRUST_PROXY=1`** behind a proxy, every client shares one rate-limit bucket and IP hashes are not recorded (duplicate detection for anonymous reports is weaker).
- **Prompt-injection detection is heuristic.** Paraphrase evades it, and severity lowering for warning context can be abused (documented in [rules.md](rules.md)).
- **Not verified on real infrastructure:** the systemd units, Caddy and Nginx configs, Docker image (CI only), security and release workflows (not yet pushed), and the GitHub OAuth flow against a real OAuth app.
